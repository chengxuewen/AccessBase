# AccessBase Gap Audit — Design / Market / UI / Service / Health

**Date**: 2026-09-23
**Method**: team-mode 5-member parallel audit (`gap-audit-2026-09-23`, members design-gap / market-gap / ui-gap / service-gap / health-gap; team deleted after delivery). Every finding carries file evidence or a zero-hit grep produced by the member that reported it. Baseline HEAD at audit time: `af6c934` (post batch-P fix waves).
**Verdict**: authentication-method breadth is at or above OSS-parity vs Keycloak / Authentik / Zitadel / Ory / Casdoor / SuperTokens. The structural gaps concentrate in (1) design-doc honesty, (2) shipped-backend-but-missing-frontend promises, (3) production foundations (transactions/pools/multi-node), (4) IAM completeness decisions (FGA/groups/eventing/logout coordination).

## D. Service / production-readiness gaps (service-gap, 31 findings distilled)

### HIGH (multi-node / durability watershed)

- **D1 zero DB transactions repo-wide** (`\.transaction(|BEGIN` = 0 hits in apps+identity): user-create + role grant (users.ts:204/270), role+permissions (roles.ts:40), tenant-suspend triple-revoke (TenantManager.ts:146-179), bootstrap 9-step, SCIM find-or-create — mid-sequence failure leaves partial state; audit write is inline but separate from business write. → wrap the funnels (start: bootstrap, user create, role binding).
- **D2 every manager builds its own Pool** (`identity/src/db/index.ts:22-25` no max; ~11 createDb call sites) → 80-100 conns/node vs PG default 100; no pool env knob, no pool metrics. → single shared memoized pool + max from env.
- **D3 migrate.sh has no pg_advisory_lock** → two replicas racing at boot abort the loser; no expand/contract migration policy; no preStop drain (readiness stays 200 to SIGTERM; pools never closed); zero-downtime upgrade undefined.

### MEDIUM

- **D4 observability**: no tracing (OTel 0 hits; only requestId), no alert rules / scrape config shipped, /metrics lacks pg-pool + redis-up + login-failure/lockout counters, log-shipping story undocumented, audit retentionDays/archiveAfterDays dead config (=A8), audit immutability convention-only (no role revoke/WORM).
- **D5 cache coherence**: permission-cache per-process 30s window, OptionsManager per-process (both self-documented ponytail), session-list Redis write WITHOUT TTL (W3 residue, `SessionManager.ts:58` — add EX), FlowToken/Lockout/rate-limit memory fallbacks = silent per-node degraded mode with no metric/alert; Redis single-host, no sentinel path.
- **D6 API surface**: **users list advertises sortBy and ignores it** (users.ts:53-54 vs UserManager.ts:167 hardcoded createdAt — fake-sort family's 2nd occurrence, now server-side); unpaginated tenants/clients/api-keys/options/permissions; no Idempotency-Key on writes; no /openapi.json artifact (/docs prod-gated); no versioning/deprecation policy text; sessions table never purged (grows forever, oidc sweeper pattern reusable).
- **D7 lifecycle**: single JWT keypair with no kid/JWKS dual-window (rotation = universe-wide invalidation; oidc keystore shares the files), backup has no scheduler/offsite/restore-drill cadence, no CHANGELOG/release/breaking-change policy, no Helm chart (Deployment+probes+PDB is the highest-leverage "production" artifact).
- **D8 sessions**: no idle/sliding timeout anywhere (absolute 7d only; stolen-at-birth refresh lives to expiry).

Clean (verified, don't re-audit): error envelope + requestId in global handler; trustProxy wired default-false; SCIM bulk honestly false; no production N+1 in loops; /metrics contract intact (route labels, in-flight symmetry).
