## 1. STILL OPEN — real-risk tier (would page someone)

### G1. Revocation reader fail-open is the documented fail-open (design, not bug) — but its DB-error surface is invisible

`utils/auth-state.ts` reader: DB error → `return null` → fail-open (allow). This is the Q3A ruling (fail-shut would brick every surface on a DB blip). **Gap:** no metric/log distinguishes "reader healthy" from "reader failing open continuously" — a dead DB would silently disable ALL revocation checks while everything looks green. **Fix shape:** one counter `accessbase_authstate_read_errors_total` + a warn line rate-limited per minute. Half-day.

### G2. `SessionManager.close()` never called on the logout path — refresh-reuse detection dormant where it matters most

round2 H6 sub-item, still true: `grep .close() routes/auth` = none. Password-reset revoke path uses the manager funnels, but plain logout doesn't close the session row's family state — **reuse detection for the JUST-LOGGED-OUT refresh token fires only via rotate, not at logout**. Impact: a stolen refresh token keeps working after the user logs out until its 7d TTL. **Fix shape:** logout handler calls `sessionManager.close(sessionId)` (family burn) — the method exists, the caller is missing. Half-day + 1 integration test.

### G3. jwks rotation = client re-create (registered debt, now with teeth)

`clients.ts` jwks is create-only; rollover requires deleting and recreating the OIDC client — **breaking every active grant/session for that client**. With private_key_jwt now live (T-PKJ), this debt got sharper: Keycloak-style monthly key rotation is routine. **Fix shape:** PUT surface for `jwks` + `backchannel_logout_uri` (also create-only today), or a `rotate-jwks` action. One day + tests.

### G4. SAML redirect-arm LogoutResponse cache-consumption gap (documented residual, logout-coherence §8)

The SLO three-arm handler answers the redirect arm without consuming the InResponseTo cache entry; protection rests entirely on the signature gate. Documented as acceptable — **carried as-is unless a real IdP forces the issue** (env-gated: needs registry).

### G5. Pagination debt trio (round2 M6, untouched)

`clients`, `api-keys`, `groups` list routes have NO pagination and NO `total` — UI paginates locally, caps at whatever the client fetches. audit vs events already duplicated pagination logic; **no shared helper exists** (grep 0). As data grows these become silent truncation bugs. **Fix shape:** one `utils/pagination.ts` (page/limit/LIMIT+count) applied to the three routes; drop-in for audit/events. One day.

### G7. admin-ui monolith quartet: Login 678 / Settings 614 / Webhooks 535 / Groups 527

Rule of 500 exceeded on four pages. Login is the worst (6 arms: password/MFA/SMS/magic/WebAuthn/oauth/SAML). Not urgent — but every branding-type slice multiplies its cost. **Fix shape:** extract per-arm components (`LoginArms/`), leave state hooks in place. One day, zero behavior change.

### G8. Device-flow user-code pages still library-default (round2 M7)

`userCode` render hooks: 1 hit in provider.ts (the enable flag) — the four HTML render hooks (userCodeInput/simple/confirm/success) are un-overridden: English-only, off design system, dark-mode mismatch. Flagged-visible surface with zero e2e. **Fix shape:** brand the 4 hooks via provider config render hooks + i18n, reuse branding slice assets. One day.

### G9. 72 bare `catch {}` blocks in production src

Census: app.ts, cache-coherence, managers, redis, FlowTokenService… Most are deliberate (fail-soft documented per Q2a/multi-node constraints), but the count is high enough that a **blanket lint rule with per-file allowlist** would force each to carry a comment explaining WHY it swallows. **Fix shape:** eslint `no-empty` with allowEmptyCatch: false + annotate existing. Half-day, mostly mechanical.
