# Review Appendix rev.2 (dual-Momus 2026-09-23: flows APPROVE-WITH-FIXES, blockers 2×HIGH absorbed)

- **R1 [HIGH, blockers] W1-4 expiry leak**: proposed UPDATE WHERE (`used_at IS NULL AND revoked_at IS NULL`) has no expiry predicate — an EXPIRED-but-unused row matches 1-row and rotates, silently dropping the expiresAt guard (current code checks it at SessionManager.ts:170-172). Absorbed: add `gt(sessions.expiresAt, new Date())` to the conditional UPDATE.
- **R2 [HIGH, blockers] W1-4 conflation contradiction**: spec mechanism said 0-rows→re-read→usedAt→revoke-all "as today" — but its own RED test demands concurrent-sibling stays INTACT. Single-row UPDATE cannot distinguish benign concurrent double-fire (sibling marked it ms ago) from serial replay (used long ago). Absorbed — 0-rows branch disambiguates: missing→not-found; revokedAt→'Session revoked' (no family burn, current parity); usedAt within CONCURRENT_GRACE_MS (10_000, named constant + ponytail note)→generic invalid-token throw, NO revoke-all (concurrent loser); usedAt older→replay→revoke-all+throw (current parity). Serial-replay test drives the old-usedAt case via direct SQL timestamp.
- **R3 [MED, both] W1-3 typing + fallback gating**: RedisLike (identity services/redis.ts:13-18) lacks getdel (FlowTokenService.test.ts:111 comment confirms) and the existing unit test asserts get+del shape — both must change. Absorbed: RedisLike gains optional `getdel?(key)`; consume uses it when `typeof === 'function'` (no casts); the error fallback is gated NARROWLY on unknown-command ReplyError only (unsupported server → get+del + WARN); all other redis errors keep existing fail-to-memory (fail-closed, never silently non-atomic under failover). Live native redis (valkey8) supports GETDEL ≥6.2 — integration test pins the atomic path.
- **R4 [MED, flows] W1-1 hermetic test impossible**: generate-keys.mjs hardcodes keysDir (:9, top-level side-effect, no exports, only --force). Absorbed: add `--out <dir>` flag; RED test runs the real script into tmpdir; write modes 0o600/0o700 via write options + explicit chmodSync (idempotent re-run upgrades existing files — Node's mode option only applies at creation).
- **R5 [LOW, flows] spec's own citations drifted** (PIT-076 irony noted): private-key write = generate-keys.mjs:**26** (not 27-28); lowercase compare = logger.ts:**215** (not 212-213); forgot-password dev-log = auth.ts:**719-721** (not 723-728); rotate SELECT = SessionManager.ts:**149-153**.
- **R6 [LOW, flows] W1-6 scope trimmed**: magic/OTP paths NEVER log their tokens today (auth.ts:792, 964 = no-token warnings) — "magic twin" removed; W1-6 = forgot-password dev-branch deletion + Dockerfile runtime-stage `ENV NODE_ENV=production` + warnDegradedChecks non-production line. W1-5 gains a one-line doc of the XFF-spoofing tradeoff (trustProxy=true requires a sanitizing proxy) in config comment + .env.example note.
- **Killed angles (blockers review, with evidence)**: batch-A gate order + G findByIdAny doors are route-level (auth.ts:551-570,582) — W1-4 internals cannot bypass; FlowTokenService takes an injected RedisLike (routes construct per-plugin) → service-level concurrency test is deterministic; trustProxy default is false (config.ts:98 === 'true') so opt-in holds; every auth request-body `code` is genuinely secret (OTP/TOTP/exchange) — response-side exemption already correct; mid-rotate UPDATE→INSERT stranding is pre-existing and unchanged (not worsened).
