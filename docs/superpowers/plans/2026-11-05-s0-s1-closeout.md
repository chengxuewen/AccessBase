### W3 — header recency lint with red/green demo (yellow: new tooling file)

- New `scripts/agents/header-lint.mts` following the two existing lint precedents:
  - checks each `docs/modules/*.md` for (a) presence of the `Implementation status` line (the
    existing D126 gate, absorbed) and (b) at least one parseable ISO date in that line, **in any
    spelling** — measured in round 2: 44/44 lines carry a date but only 7 use the `as of` prefix;
    the legacy forms `(2026-09-23 gap audit)` / `(…, updated 2026-10-08)` must parse or every
    KEPT-HONEST-STALE header would fail the bar the plan itself declares legal (R2-C1 — the C-2
    hole was open again at the parser level). **Error-level** = missing line / no date in any
    spelling; the full `(as of <date>, evidence: …)` shape binds REWRITTEN headers only (the
    convention holds 7/7 measured), never kept-stale ones;
    (c) staleness beyond a configurable window (default 45 days, any spelling) and
    fresh-but-anchorless are **warn-level** triage inputs, not format violations (panel C-2
    severity split, unchanged);
  - exemptions: the superseded-set and the informational one — the list is derived at run time
    from the headers' own text (`superseded by` / `informational` markers) plus a
    `--self-test` fixture set; machine-checkable per R2-X3=B: a row claiming freshness must carry
    its evidence anchor (`evidence:` present when the verdict was rewritten — the
    `(as of <date>, evidence: …)` shape is already the convention in the 7 rewritten headers);
  - `--self-test` fixtures: planted stale date → RED, planted missing date → RED, planted
    evidence-less fresh date → RED, clean sample → GREEN (the red/green demo the S1 acceptance
    requires, performed **inside the same commit** as the tool);
  - **wiring is two-staged (panel C-1, HIGH — the plan must not lock its own repo)**: the tool
    lands in REPORT mode (findings printed, exit 0), because the measured pre-commit IS an
    `agents sync → agents check` chain and an error-level lint landing before W4 cleaned the
    stale verdicts would block every subsequent commit, W4's own batches included. Strict mode
    (`--strict` ⇒ exit 1 on error-level findings) flips on at W4's exit as part of the S1
    acceptance. **X-1 RULED 2026-11-05 = A**: strict rides `agents check`, i.e. double
    enforcement via the measured chain (local pre-commit + CI Governance Gates, which rerun the
    same check) — the 46-day silent-rot class gets a mechanical gate, not a trust-based one; the
    error-level bar stays narrow (format violations only; staleness is warn and never blocks).
  - registered into the `scripts/agents/agent-targets.json` lint layer (the fifth of the "4
    lints" registry — exact wiring read at execution time).
  - **the strict-flip ships green-in-the-same-commit (round 2 R2-C3)**: because strict rides
    `agents check` (X-1=A) and pre-commit runs the check, the flip commit must be W4's exit
    commit itself (or later) — flipping in a separate earlier commit would red its own
    pre-commit. W3 therefore lands report-mode only; the `--strict` flag exists from W3 but the
    check-chain wiring happens at W4 exit.
- Also registers (does NOT fix) the known tsc blind spot: `scripts/agents/*.mts` are outside
  tsconfig include (recorded in the 11-04 governance session; a one-line include change is a
  separate ruling if W2's run shows it matters).
- Acceptance: the tool runs report-mode clean; red/green demo via `--self-test` fixtures pasted
  into the commit message; plan §S1 lint deliverable marked delivered with the demo reference
  (strict wiring deferred to X-1 + W4 exit).
