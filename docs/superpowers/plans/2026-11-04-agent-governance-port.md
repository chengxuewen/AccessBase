**Design principles ported from the three repos:**

1. **Single source, generated everything else** (VE D28/D41; RCH D18): `.agents/` is the only
   hand-edited layer; host-visible layers are regenerated by `sync` and asserted byte-equal by
   `check`. A declared layer that is missing is a hard error, never a silent skip.
2. **Hooks generate, gates verify** (RCH D21 / RCH:PIT-250): a pre-commit hook is best-effort
   (a fresh clone has no hooks); every hook-enforced invariant must also exist as a lint/gate
   that runs in the checked-in CI chain.
3. **Red/green duty** (RCH CONSTRAINTS "verification discipline"; VE C19): a new or modified
   gate must be demonstrated once with "deliberate violation → RED, restored → GREEN", with
   command and result recorded in the commit message. A check reported as "enforced" without a
   negative demonstration counts as not done. Where feasible, embed `--self-test` synthetic
   fixtures (changeid-lint pattern) that never touch real data.
4. **Token economics are explicit** (MS D199/D213; VE D47/D49): every per-turn instruction has
   a measured cost; the memory hub carries a dual-unit budget (chars + bytes, because CJK
   splits the two); always-on rule surface stays minimal (2 rules), the rest routes by
   description.
5. **Lessons escalate to machines** (MS lesson-memory): any pitfall repeated ≥2 times or costing
   >3 turns of localization must graduate into a rule, gate, or hook — "be careful next time"
   is not an artifact.
6. **Citation discipline** (VE anti-pattern "never cite predecessor numbering"): references to
   the reference repos' numbering MUST carry a repo prefix (`MS:` / `VE:` / `RCH:`) and are
   exempt from local rule-ref-lint resolution; bare cross-repo numbers are treated as dangling.

**Global constraints:**

- English for everything persisted (conventions.md 2026-09-21 hard constraint) — this plan
  included; Chinese only in live chat.
- No `as any` / `@ts-ignore` / `@ts-expect-error`; `bash accessbase.sh typecheck` double-green
  before any commit; vitest 1556 + e2e 184 baselines, 0 new failures.
- No auto-commit: every `git add`/`git commit` needs explicit user sanction in that turn (C1
  equivalent in this repo's workflow).
- `.refinfo/` stays read-only and excluded from all searches.
- Generator stack decision (ADJ-2a ruled A): TypeScript under `scripts/agents/` executed via
  `pixi run node` — matches this repo's pnpm/TS stack and existing script precedents
  (`scripts/gen-api-inventory.mts`, `scripts/re-encrypt.ts`). RCH chose stdlib-only Python for
  bare-CI-runner reasons that do not apply here (pixi already manages node). Runtime fact
  (review-verified 2026-11-04): `pixi.lock` resolves **nodejs 26.6.0** (constraint `>=20`),
  so native `.ts` execution (type stripping, stable since node 23.6) holds with headroom;
  `.node-version` (=22) is advisory only. Guard: if a future `pixi update` re-resolves node
  below 22.6, generators must switch to `.mts`/`tsx` before running — record as a PIT if
  ever hit.
  SECOND data point (ADJ-7f, measured 2026-11-04): the generators also run correctly under the
  SYSTEM node **22.23.2** with no flag — type stripping is on by default in 22.18+. Consequence:
  a CI governance job needs neither pixi nor `--experimental-strip-types`, but it must resolve
  `node-version: '22'` to ≥22.18 (earlier 22.x untested here — do not assume), and the
  `gate-mcp` pin check needs `node_modules`, so `pnpm install --frozen-lockfile` is mandatory
  in that job.
- Baseline verification commands: `bash accessbase.sh typecheck` / `test` / `lint`.
