## 总评

当前设计是一个**可用但不够精致**的 4 步向导。基本框架正确——环境检查 → 管理员创建 → 配置 → 完成——但与调研文档中的 7 个主流项目对比，存在多处设计缺口。以下按维度展开。

---

## 1. 流程直觉性

### 1.1 步骤设计（⭐⭐⭐ 良好，有改进空间）

当前 4 步流程：

```
欢迎+系统检查 → 创建管理员 → 基础配置 → 完成
```

**优点**：

- 每步只做一件事，认知负担低
- 系统检查前置是正确做法（WordPress、Directus 也这样做）
- SMTP 可选 + 跳过按钮符合"最少必要字段"原则

**问题**：

| #   | 问题               | 严重度 | 说明                                                                                                              |
| --- | ------------------ | ------ | ----------------------------------------------------------------------------------------------------------------- |
| F1  | 缺少语言选择步骤   | 中     | WordPress 和 NocoBase 在向导第一步提供语言选择。调研建议也明确提到。当前 i18n 翻译键已准备好，但没有语言选择 UI。 |
| F2  | 步骤不可跳过       | 低     | 当前设计强制线性流程。如果系统检查全部通过，应允许直接跳到管理员创建，减少等待感。                                |
| F3  | 无进度保存         | 高     | 如果用户在步骤 3 填写完表单后浏览器崩溃，所有数据丢失。Zustand store 仅存内存，应持久化到 localStorage。          |
| F4  | 完成后无引导式教程 | 中     | Strapi 的 Guided Tour 被调研报告列为 UX 最佳实践。当前 CompleteStep 只有快速链接，缺少功能引导。                  |

### 1.2 信息架构（⭐⭐⭐ 良好）

**优点**：

- 系统检查与管理员创建分离（技术 vs 用户信息）
- 配置步骤的必填/可选分组合理

**问题**：

| #   | 问题                   | 说明                                                                                                     |
| --- | ---------------------- | -------------------------------------------------------------------------------------------------------- |
| F5  | 步骤 3 配置项偏少      | 调研建议包含 JWT Secret 自动生成、HTTPS 选项、认证方式选择（本地/LDAP/OAuth）。当前只有站点名称和 SMTP。 |
| F6  | 缺少环境变量预配置支持 | Directus、Keycloak、NocoBase 都支持通过环境变量跳过浏览器向导。当前设计未提及。                          |

## 2. 错误处理 UX

### 2.1 当前设计（⭐⭐ 可用，细节不足）

文档第 8 节列出了三种错误场景，但描述过于笼统。

**问题**：

| #   | 问题                       | 严重度 | 说明                                                                                                                                                                            |
| --- | -------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1  | 系统检查失败无具体恢复指引 | 高     | 仅说"显示具体错误信息 + 重试按钮"。但数据库连接失败时，用户需要知道：检查什么？改哪里？应提供可操作的错误信息，如"请确认 PostgreSQL 服务已启动，并检查 DATABASE_URL 环境变量"。 |
| E2  | 表单提交无 loading 状态    | 中     | `createAdmin` 和 `saveConfig` 是异步 API 调用，但代码示例中没有展示提交时的 loading 状态、防重复提交、按钮禁用等。                                                              |
| E3  | 网络错误无自动重试         | 低     | "通用错误提示 + 重试按钮"是最基本的处理。对于网络抖动，应考虑自动重试（3 次，指数退避）。                                                                                       |
| E4  | 无错误状态的视觉设计规范   | 中     | 未定义错误提示的样式：是用 `message.error()`、`notification.error()` 还是行内 `Form.Item` 错误？三者用途不同，应明确。                                                          |
| E5  | 后端错误码未规划           | 中     | API 设计只有成功路径，没有定义错误响应格式（如 `{ code: 'ADMIN_EXISTS', message: '...' }`）。                                                                                   |

### 2.2 建议的错误处理策略

```
系统检查失败 → 行内错误（每个检查项旁）+ 恢复建议 + 重试按钮
表单验证失败 → Form.Item 行内错误（红色文字）
API 提交失败 → notification.error（右上角弹窗，含错误码和建议操作）
网络断开 → 全局 banner（页面顶部，黄色警告条）
```

## 3. 移动端适配

### 3.1 当前设计（⭐⭐ 不足）

文档中关于移动端的内容仅有一句：

> "卡片宽度：800px（桌面端），100%（移动端）"

**问题**：

| #   | 问题                   | 严重度 | 说明                                                                                        |
| --- | ---------------------- | ------ | ------------------------------------------------------------------------------------------- |
| M1  | 无响应式断点定义       | 高     | 未定义 `sm`/`md`/`lg` 断点。800px 卡片在平板（768px）上会溢出。                             |
| M2  | Steps 组件移动端未处理 | 高     | Ant Design 的 `Steps` 在窄屏下会水平挤压。应使用 `direction="vertical"` 或 `size="small"`。 |
| M3  | 表单布局未考虑移动端   | 中     | 管理员表单有 4 个字段，配置表单有 7+ 个字段。移动端应使用全宽布局，标签在上。               |
| M4  | 无触摸目标尺寸规范     | 中     | 移动端按钮/链接最小触摸目标应为 44×44px（WCAG 2.5.5）。                                     |
| M5  | 系统检查列表移动端表现 | 低     | 长错误信息在窄屏上可能溢出或换行混乱。                                                      |

### 3.2 建议方案

```typescript
// 响应式卡片宽度
<Card style={{ width: '100%', maxWidth: 800, margin: '0 16px' }}>

// 响应式 Steps
const { md } = Grid.useBreakpoint();
<Steps direction={md ? 'horizontal' : 'vertical'} current={current} />

// 响应式表单
<Form layout={md ? 'horizontal' : 'vertical'}>
```

## 4. 无障碍性（Accessibility）

### 4.1 当前设计（⭐ 未考虑）

文档中**没有任何无障碍性相关设计**。这对企业级产品是不可接受的。

**缺失项**：

| #   | 缺失                                  | WCAG 条款 | 严重度 |
| --- | ------------------------------------- | --------- | ------ |
| A1  | 无 ARIA landmark                      | 1.3.1     | 高     |
| A2  | 步骤组件无 `aria-current`             | 4.1.2     | 高     |
| A3  | 表单无 `aria-required`/`aria-invalid` | 3.3.1     | 高     |
| A4  | 错误信息无 `aria-live`                | 4.1.3     | 中     |
| A5  | 系统检查状态无屏幕阅读器文本          | 1.1.1     | 中     |
| A6  | 无键盘导航支持                        | 2.1.1     | 高     |
| A7  | 焦点管理未定义                        | 2.4.3     | 中     |
| A8  | 颜色对比度未验证                      | 1.4.3     | 中     |

### 4.2 具体建议

```typescript
// 步骤组件
<Steps
  current={current}
  aria-label="设置向导进度"
  items={steps.map((s, i) => ({
    ...s,
    ariaLabel: `步骤 ${i + 1}: ${s.title}`,
  }))}
/>

// 表单字段
<Form.Item
  name="email"
  rules={[{ required: true, message: '请输入邮箱' }]}
  // Ant Design Form 自动添加 aria-required 和 aria-invalid
>

// 步骤切换时焦点管理
useEffect(() => {
  // 步骤切换后将焦点移到步骤标题
  stepTitleRef.current?.focus();
}, [current]);

// 系统检查状态（屏幕阅读器）
<span className="sr-only">
  {check.status === 'success' ? '检查通过' :
   check.status === 'error' ? `检查失败: ${check.message}` :
   '检查中'}
</span>

// 错误信息实时播报
<div role="alert" aria-live="polite">
  {errorMessage}
</div>
```

### 4.3 色彩对比度

当前配色方案需要验证：

| 元素         | 前景色    | 背景色  | 对比度 | WCAG AA 要求          |
| ------------ | --------- | ------- | ------ | --------------------- |
| 主要按钮文字 | #fff      | #1890ff | 4.56:1 | ✅ 通过（4.5:1）      |
| 错误文字     | #ff4d4f   | #fff    | 3.93:1 | ❌ 不通过（需 4.5:1） |
| 次要文字     | #00000073 | #fff    | 5.65:1 | ✅ 通过               |

### 5.3 差距分析

**最大差距（必须补齐）**：

1. **安装后禁用 setup 端点**：这是一个安全漏洞。WordPress 和 Directus 都因此被攻击过。必须在 `/setup/complete` 成功后标记系统为"已初始化"，后续所有 `/setup/*` 接口返回 404。
2. **进度保存**：企业用户可能在配置过程中被打断（会议、浏览器崩溃等），丢失数据会严重影响体验。
3. **环境变量预配置**：DevOps 团队期望自动化部署，不希望通过浏览器手动操作。

**中等差距（建议补齐）**：

4. **语言选择**：企业产品面对国际化团队，这应该是 P1 而非缺失。
5. **连接测试**：SMTP 测试连接从 P2 提升到 P1，数据库连接测试应加入。
6. **引导式教程**：Strapi 的 Guided Tour 是显著的 UX 亮点。

## 6. 额外发现

### 6.1 代码质量问题

| #   | 问题                  | 说明                                                           |
| --- | --------------------- | -------------------------------------------------------------- |
| C1  | `formData` 类型不安全 | `useState({})` 使用空对象，应定义明确的类型联合                |
| C2  | 步骤组件全量渲染      | `stepComponents` 数组每次渲染都创建所有组件，应只渲染当前步骤  |
| C3  | 无路由保护            | `/setup` 路由没有防护已完成初始化的系统再次访问                |
| C4  | 内联样式              | 大量 `style={{...}}` 应提取为 CSS Modules 或 styled-components |

### 6.2 设计文档缺口

| #   | 缺失内容          | 说明                                                            |
| --- | ----------------- | --------------------------------------------------------------- |
| D1  | 无线框图/原型     | 仅有代码片段，缺少视觉稿                                        |
| D2  | 无用户旅程图      | 缺少完整的用户旅程（包括异常路径）                              |
| D3  | 无状态机定义      | 步骤流转缺少明确的状态机（如：检查中→检查失败→重试中→检查通过） |

| D5  | 无性能要求        | 表单提交、系统检查的超时时间未定义                              |

## 7. 改进建议（按优先级）

### P0（必须修复）

1. **安装后禁用 setup 端点**：在 `/setup/complete` 中标记系统已初始化
2. **表单数据持久化**：使用 localStorage 或 sessionStorage 保存已填数据
3. **加载状态**：所有 API 调用添加 loading 状态和防重复提交
4. **键盘导航**：确保 Tab 键可遍历所有交互元素

### P1（重要）

5. **语言选择步骤**：在欢迎页或独立步骤中添加
6. **SMTP 连接测试**：从 P2 提升到 P1
7. **错误信息可操作化**：每个错误附带恢复建议
8. **响应式断点**：定义 `sm`/`md`/`lg` 断点和对应布局
9. **ARIA 标签**：为所有交互元素添加无障碍属性
10. **环境变量预配置**：支持 `ADMIN_EMAIL`/`ADMIN_PASSWORD` 跳过向导

### P2（优化）

11. **引导式教程**：首次登录后的功能引导
12. **密码强度指示器**：实时显示密码强度
13. **自动 HTTPS 建议**：检测并推荐 HTTPS 配置
14. **无线框图补充**：添加每个步骤的视觉稿

---

## 8. 结论

当前设计提供了合理的功能框架，但与行业最佳实践存在显著差距，主要集中在：

- **安全性**：缺少安装后端点保护、密码自动生成、JWT Secret 管理
- **健壮性**：缺少进度保存、加载状态、错误恢复
- **无障碍性**：几乎完全缺失
- **移动端**：仅有最基本的响应式处理

建议在实施前先补齐 P0 和 P1 项，特别是安全相关的改进（安装后端点保护是**阻塞项**）。
